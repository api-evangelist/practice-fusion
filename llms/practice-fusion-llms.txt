# Practice Fusion

> Practice Fusion is a cloud-based electronic health record (EHR) platform for independent ambulatory medical practices, and a Veradigm company. Its developer surface is an ONC Certified FHIR R4 (Patient Data Sharing / PDS) API implementing US Core 6.1.0, SMART App Launch 2.0.0, and Bulk Data Access 1.0.1 over SMART-on-FHIR OAuth2, a Patient Fusion personal-health-record API, HL7 v2 bi-directional Labs and Imaging interfaces, and a partner marketplace. Generated by the API Evangelist enrichment pipeline from Practice Fusion's own published documents; not published by Practice Fusion.

## APIs

- [Practice Fusion FHIR API (Patient Data Sharing)](https://www.practicefusion.com/fhir/): FHIR R4 (v4.0.1) read/search across 47 resource types. Per-organization base URLs: https://api.practicefusion.com/fhir/r4/v1/{organizationId} (provider/system) and https://api.practicefusion.com/fhir/fmh/r4/v1/{organizationId} (patient). 47 resources support read, 45 support search; Group also supports create/update and $export.
- [Patient Fusion PHR API](https://www.practicefusion.com/pds-api/developer-guide/): Patient-facing personal health record API at https://api2.practicefusion.com/phr/patient/v1, authorized by https://auth.patientfusion.com/ (OAuth 2.0 + OpenID Connect).
- [Practice Fusion Labs API](https://www.practicefusion.com/labs-documentation/): HL7 v2.3 / v2.5.1 bi-directional lab order and result integration (Labcorp, Quest, RadNet, SimonMed, Rayus).
- [Practice Fusion Imaging API](https://www.practicefusion.com/imaging-documentation/): HL7 v2 bi-directional imaging order and radiology-result integration.

## Authentication

- [SMART-on-FHIR OAuth2](https://www.practicefusion.com/fhir/api-specifications/): authorization_code, client_credentials and refresh_token grants; PKCE S256 only; confidential-symmetric, confidential-asymmetric (JWKS) and public clients; OpenID Connect; optional mutual-TLS client certificates.
- Scopes follow SMART v2 grammar `<context>/<Resource>.<cruds>`; the API is read/search, so `.rs` is the operative access.
- Register at the [PDS API Portal](https://pfpds.practicefusion.com/s/Registration). Approval is manual, credentials arrive by email, and there is no self-serve key.

## Discovery

- SMART configuration (provider): https://api.practicefusion.com/fhir/r4/v1/{organizationId}/.well-known/smart-configuration
- SMART configuration (patient): https://api.practicefusion.com/fhir/fmh/r4/v1/{organizationId}/.well-known/smart-configuration
- CapabilityStatement: https://api.practicefusion.com/fhir/r4/v1/{organizationId}/metadata
- JWKS: https://api.practicefusion.com/fhir/r4/v1/{organizationId}/.well-known/jwk
- Patient Fusion OIDC discovery: https://auth.patientfusion.com/.well-known/openid-configuration
- Service Base URL directory (every practice, as a FHIR Bundle): https://www.practicefusion.com/assets/static_files/ServiceBaseURLs.json

## Runtime behaviour

- Media type: `application/fhir+json` on request and response.
- Errors: FHIR `OperationOutcome`, not RFC 9457 `application/problem+json`.
- Pagination: searchset `Bundle`; follow `link[relation=next].url`, size with `_count`.
- Rate limits: enforced on every call, 429 on exhaustion, no published numbers and no rate-limit response headers.
- Bulk export: `Group/{id}/$export`, async, 202 + `Content-Location` poll, NDJSON output.
- No sandbox, no webhooks, no FHIR Subscription resource, no MCP server and no A2A agent card.
